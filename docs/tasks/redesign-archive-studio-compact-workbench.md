# Archive Studio 紧凑工作台重设计

## 目标

- 只重做本地 Archive Studio 的编辑界面，不改变公开收藏展示端。
- 依据 `YuDesign` 的内容优先、细线分区、低按钮感和双字体原则，统一四板块表单。
- 降低纵向占用，让常用新建 / 修改流程尽可能在一个桌面视口内完成。
- 保留真实展示预览、preview、preflight、保存、检查和公开同步能力。

## 当前问题

- 章节标题、字段标签和解释文字重复占用纵向空间。
- 两列表单不能充分利用桌面宽度；长输入框和多行框尺寸远超实际填写需求。
- 素材选择器表现为大块卡片，文件选择这一简单动作占用过多面积。
- 各板块虽然使用相同 CSS，但控件密度和字段排列缺少稳定节奏。
- 固定操作栏和较长右侧检查内容进一步压缩首屏工作空间。

## 设计规则

- 桌面章节采用“窄标题列 + 内容列”，用细线分区，不给每段增加卡片外框。
- 表单采用三列网格；普通字段占一列，宽字段占两列，长正文单独占内容列。
- 输入与选择控件使用 36px 视觉高度；短备注约 54px，Markdown 约 130px。
- 类型选择器隐藏解释副标题，保留图标与类型名。
- 必填状态使用陶土色星号，不使用胶囊标签。
- 素材使用紧凑文件行；格式信息退后，文件名保持可扫描。
- 右侧预览与检查限制在视口内滚动；底部操作坞降低高度。
- 手机端恢复单列和足够点击面积，不机械缩小桌面三列布局。

## 安全边界

- 不修改 Archive、旧 Data、公开 JSON、缓存、reports 或生成器。
- 不改变表单字段、payload、preview、preflight、写入或同步逻辑。
- 不把 Studio 重新加入公开站入口或生产展示路由。
- 不运行生成、发布或 Git 写入命令。

## 验证

- TypeScript 静态检查和现有 Studio 更新事务检查通过。
- Music、Texts、Visions、Games 桌面首屏检查控件密度、字段顺序和操作栏遮挡。
- 390px 窄屏可完成同一流程，无横向溢出、文字遮挡或过小点击区域。
- 公开 Games、Visions、Music、Texts 页面无视觉或运行时回归。

## 实施结果

- 已按 YuDesign 规则统一 Studio 的暖纸色、陶土色操作强调、衬线章节标题和无衬线表单控件。
- 四板块桌面表单改为紧凑三列与窄章节标题列；Music、Texts、Visions、Games 的左侧编辑区在 1280 x 720 视口内均可完整显示。
- 输入框统一为 36px 桌面高度；短备注、正文、类型选择和素材行均按真实内容需求缩短，不再使用大块说明卡片。
- 390px 窄屏保持单列，输入与选择控件为 44px，底部操作区隐藏重复状态摘要且无横向溢出。
- `npx tsc --noEmit` 和 `node scripts/check-archive-studio-updates.mjs` 均通过；公开 Music 页面可正常加载。
- 本任务没有修改公开展示组件、Archive 数据、旧 Data、派生 JSON、缓存、reports、生成器或发布流程。

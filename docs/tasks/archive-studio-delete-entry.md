# Archive Studio 整条目删除

## 目标

- 在四板块“修改”模式右下角提供删除条目操作。
- 删除 Archive 中该条目的完整目录，包括 entry.yaml、content.md 和条目素材。
- 已公开条目建立待同步删除记录；公开网页仍由现有“同步”动作显式更新，不自动发布。
- 删除前备份条目目录，写后结构检查失败时自动回退。

## 用户流程

1. 进入修改模式并选择条目。
2. 点击右下角“删除条目”。
3. 在确认窗口核对板块、标题和删除范围。
4. Studio 自动执行删除预览、首页引用检查和一次性 token 预检。
5. 通过后删除完整条目目录并运行板块结构检查。
6. 页面回到未选择状态；已公开条目显示待同步。

## 安全边界

- 只允许删除 Music album、Texts 三种普通条目、Visions movie / series 和 Games normal_game。
- 首页精选仍引用该条目时阻断删除，必须先在首页管理中替换。
- 不删除旧 Data，不触发发布、Git 或 build_archive.py。
- 不自动清理旧共享缓存；公开站自身的 Studio 媒体只在显式同步时清理。
- 一次性 delete token 与 board、entry id 和目录摘要绑定，不能重放。

## 验收

- 四板块删除 preview / preflight / apply 在系统临时目录通过。
- 删除后完整条目目录不存在，板块 shape 检查通过，旧源快照不变。
- token 重放被阻断，失败场景恢复完整条目目录。
- 首页引用条目被阻断。
- 已公开条目同步后从板块 JSON 移除；非 Studio 共享媒体不误删。
- 浏览器中删除按钮只在修改模式和已选条目时出现。

## 实施结果

- 已建立四板块共用的 delete preview、preflight、一次性 token、整目录备份、apply 和 rollback。
- 系统临时目录回归覆盖四板块完整目录删除、首页引用阻断、token 重放阻断、失败自动恢复和公开删除同步。
- 已公开条目删除后生成 pending-public-deletes 记录；显式同步时从板块 JSON 移除，并只清理 Studio 自有媒体，不清理旧共享缓存。
- 四板块修改模式右下角均已接入“删除条目”，确认窗口使用页面顶层显示，桌面和 390px 窄屏均不被顶栏或底栏遮挡。
- 删除成功后清空当前选择、刷新条目列表和同步状态；公开发布仍不会自动触发。
- 真实 Archive 仅执行过 delete preview 只读验证，没有执行真实删除。
- 2026-08-26：修复 Games 删除 apply 的过期赛季基线。此前删除安全检查固定要求 0 个赛季，真实 Archive 存在赛季时会在事务开始前失败并只显示通用 API 错误；现在按当前 Games v2 目录动态计算赛季数量。
- 修复后已在真实条目上完成 delete preview / preflight 只读验证，预检通过且未执行删除。

## 回退

- 删除事务保留条目目录备份和 rollback manifest。
- 失败会自动恢复；成功后的人工恢复使用对应 transaction 备份。
- 回退代码时移除 delete API、共用删除组件和待同步删除处理，不改现有条目格式。

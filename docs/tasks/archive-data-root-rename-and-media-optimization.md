# 数据 Archive 改名与公开媒体优化

## 目标

1. 将当前维护数据目录从 `ArchiveData-v2` 安全迁移为 `Archive`；
2. 让运行代码通过统一路径配置读取和写入数据 Archive；
3. 保持旧 OneDrive `Data` 只读；
4. 为 Archive Studio 公开同步增加独立媒体派生层；
5. 原始素材保留在数据 Archive，公开目录只保存优化副本。

## 路径边界

- 项目 Archive：项目 Git 工作树；
- 数据 Archive：OneDrive 当前维护数据目录；
- 旧 Data：只读迁移来源和回退备份；
- 新旧维护目录同时存在时禁止写入，避免数据分叉。

## 迁移顺序

1. 集中路径常量并兼容迁移前旧目录；
2. 在旧目录状态下运行全部检查；
3. 停止 Archive Studio API；
4. 在系统临时目录记录文件清单、大小和 SHA-256 基线；
5. 使用同卷目录重命名，不复制、不删除文件内容；
6. 验证新目录文件数、目录数和哈希一致，旧目录不存在；
7. 切换活跃文档和用户可见名称；
8. 再实施媒体派生优化。

## 媒体规则

| 角色 | 公开输出 |
|---|---|
| Games cover | 600×900 WebP |
| Visions poster | 清理边缘后 600×900 WebP |
| Music cover | 保持比例，最长边 1200px，WebP |
| Texts cover | 保持比例，最长边 1200px，WebP |
| Music audio | MP3/WAV/FLAC 转 192 kbps AAC/M4A；兼容格式按策略复制 |

媒体转换先写系统临时目录，校验后再原子替换公开文件。preview 只显示相对路径、输入输出格式、尺寸和大小，不显示完整本机路径。

## 禁止

- 不运行 `build_archive.py`；
- 不修改旧 OneDrive Data；
- 不覆盖或压缩数据 Archive 中的原始素材；
- 不自动发布；
- 不在转换失败时更新公开 JSON；
- 不让新旧维护目录同时接受写入。

## 验收

- 路径迁移前后文件和 SHA-256 基线一致；
- 四板块 shape check 通过；
- Studio create / update / homepage / public sync 回归通过；
- 媒体 preview、转换、checksum、失败回退和幂等测试通过；
- 公开 JSON 只引用已存在的优化媒体；
- 生产构建及桌面、移动浏览器验收通过。

## 回退

- 路径迁移提交前：将目录原名恢复并使用旧代码；
- 路径迁移提交后：代码兼容层可识别唯一存在的旧目录，但双目录状态始终阻断；
- 媒体同步失败：恢复公开 JSON 和被替换媒体，删除本次新建媒体；
- 已提交代码：按分组 Git revert，不修改旧 Data。
